# ТЗ: профориентационный тест «Воплощение»

> Автоконвертация из source/tz_proftest.docx. Тексты вопросов — дословно, ID постоянные.


## 1. Термины


| Термин | Значение |
|---|---|
| RIASEC | Шесть типов интересов по Холланду: R — реалистичный, I — исследовательский, A — артистический, S — социальный, E — предприимчивый, C — конвенциональный. |
| Домен МОГУ | Область мини-заданий: logic (логика), numbers (числа), text (текст), space (пространство), people (люди). |
| Сфера | Одно из семи направлений результата: business, finance, it, engineering, biology, telecom, public_service. |
| Условия (NEED) | Восемь условий хорошей работы из части 4А (автономия, рост, связь и т. д.). |
| Совпадение, % | Итоговый процент соответствия сфере: Итог ÷ 71 × 100, округление до целого. |
| A, B, C, D, E | Пять слагаемых итога по сфере (раздел 8.6). Не путать с типом RIASEC «A» и вариантом ответа «А»: в коде используйте имена `scoreInterest`, `scoreRiasec`, `scoreAbility`, `scoreValues`, `scoreNeeds`. |


## 2. Сценарий пользователя

1. Пользователь открывает страницу теста и видит приветствие, время прохождения (45–55 минут), дисклеймер и кнопку «Начать».  
2. Принимает согласие на обработку данных (если требуется, см. раздел 14) и заполняет Часть 0.  
3. Проходит части 1–5 последовательно. Каждая часть — несколько экранов; на экране 1–5 вопросов.  
4. После каждого экрана ответы автоматически сохраняются; можно закрыть страницу и вернуться.  
5. После Части 5 нажимает «Показать результат». Алгоритм считает результат и открывает экран результата.  
6. Пользователь может скачать результат (PDF), пройти тест заново, написать в поддержку.  
7. Результат остаётся доступным по персональной ссылке.

| Часть | Название | Вопросов | Тип ввода | Участвует в расчёте |
|---|---|---|---|---|
| 0 | Знакомство | 6 | поля формы | нет (для персонализации) |
| 1А | Интересы: выбор пары | 15 | выбор А/Б | да: RIASEC |
| 1Б | Ценности | 10 пунктов | топ-3 и 2 «наименее важно» | да: D |
| 1В | Три вопроса о себе | 3 | текст | нет (показывается в результате) |
| 1Г | Интерес к сферам | 14 | шкала 1–5 | да: A |
| 2А | Мини-задания | 10 | один из 3–4 вариантов | да: C |
| 2Б | Реальный опыт | 5 | текст + шкала 1–5 | нет (показывается в результате) |
| 3 | НАДО: ограничения | 6 + 1 | один вариант + текст | нет (условные подсказки, 9.6) |

| 5 | Проверка согласованности | 5 | выбор А/Б | да: предупреждение |

Приоритеты: Must — обязательно в первой версии; Should — желательно; Could — по возможности.

| FR-02 | Кнопка «Назад» сохраняет введённые ответы. Кнопка «Далее» неактивна, пока не заполнены обязательные поля экрана. | Must |
| FR-03 | Автосохранение после каждого экрана. При повторном заходе пользователь продолжает с последнего неотвеченного экрана. | Must |
| FR-04 | Все вопросы частей 1А, 1Б (кроме пояснений), 1Г, 2А, 3 (NAD01–NAD06), 4А, 5 обязательны. Открытые вопросы (1В, 2Б, 4Б, NAD07) и PRF01 не обязательны. | Must |
| FR-05 | Часть 1Б: ровно три ценности с рангами 1, 2, 3 и ровно две отмеченные как «наименее важно». Одна ценность не может быть в обоих списках. Остальные пять остаются нейтральными. | Must |
| FR-06 | Часть 4А: оценка каждого из 8 условий от 1 до 5 и выбор ровно трёх самых важных условий (вне зависимости от оценок). | Must |
| FR-07 | Часть 1А и Часть 5: два варианта показываются как две крупные кнопки-карточки. Порядок вопросов внутри 1А рекомендуется перемешивать случайно, расположение вариантов слева/справа тоже. В данных всегда сохранять тип выбранного варианта, а не положение. | Should |
| FR-08 | Часть 2А: порядок вариантов ответа не перемешивать. Верный ответ пользователю не показывать ни в процессе, ни в результате. | Must |
| FR-09 | Открытые ответы: поле до 1000 символов, счётчик символов. Для 2Б шкала энергии (1–5) обязательна, только если введён текст кейса. | Must |
| FR-10 | Расчёт выполняется на сервере по алгоритму раздела 8 (клиентская копия допустима только для предпросмотра). Функция расчёта чистая: зависит только от ответов. | Must |
| FR-11 | Экран результата содержит блоки из раздела 9 в указанном порядке. | Must |
| FR-12 | Результат сохраняется и открывается по персональной ссылке с неугадываемым идентификатором (не более 128 бит случайности). | Must |
| FR-13 | Выгрузка результата в PDF. | Should |
| FR-14 | Отправка результата на e-mail по желанию пользователя. | Could |
| FR-15 | Повторное прохождение сохраняет предыдущие результаты как отдельные записи; пользователь может открыть любую из своих попыток. | Should |
| FR-16 | Аналитические события: начало теста, завершение каждой части, выход (по последнему экрану), завершение, открытие результата, скачивание PDF. | Should |
| FR-17 | Тексты, веса, пороги и профили сфер вынесены в конфигурацию (файл или таблица базы данных), а не зашиты в код, чтобы их можно было менять без выпуска версии. | Must |


## 5. Типы экранов и полей


| Тип | Поведение | Где используется |
|---|---|---|
| pair | Два варианта, нужно выбрать один. Выбор сразу сохраняется, переход к следующему вопросу по кнопке «Далее». | 1А, 5 |
| rank_values | Список из 10 карточек. Пользователь нажимает карточку и выбирает «1», «2», «3» или «наименее важно». Счётчик показывает, сколько ещё нужно выбрать. Нельзя выбрать больше лимита. | 1Б |
| likert5 | Утверждение и пять кнопок 1–5 с подписями крайних значений («совсем не интересно» / «очень интересно» или «совсем не важно» / «критически важно»). | 1Г, 4А |
| pick3 | Выбор ровно трёх из восьми карточек после оценок. | 4А (после NEED01–08) |
| single_choice | Один вариант из списка (радио-кнопки), для 2А варианты в заданном порядке. | 2А, 3, PRF06 |
| text | Многострочное поле, до 1000 символов. | 1В, 2Б, 4Б, NAD07 |
| energy5 | Оценка энергии от 1 («выжало») до 5 («зарядило»). | 2Б |

Для мобильных (ширина от 360 px) все элементы должны быть удобны для нажатия пальцем: область нажатия не менее 44 × 44 px.

### 6.7. Часть 2Б. Реальный опыт (text + energy5, не оцениваются)

## 7. Алгоритм подсчёта


### 7.1. Баллы типов RIASEC

Для каждого INT01–INT15: если выбран вариант А, +1 к типу из «Тип А», иначе +1 к типу из «Тип Б». Результат: `riasec` = { R, I, A, S, E, C }, каждое значение 0–5, сумма 15.  
Код интересов (для показа) — три типа с наибольшими баллами. При равенстве баллов выше ставится тип, победивший в прямой паре этих двух типов (такая пара есть в INT01–INT15). Если равны три и более типов и победители образуют круг, применяется порядок R, I, A, S, E, C.  
Уровни типа: 4–5 «выраженный», 2–3 «умеренный», 0–1 «слабый».  

### 7.2. Баллы доменов МОГУ

Для каждого TSK01–TSK10: если ответ совпал с ключом, +1 к домену задания. Результат: `domains` = { logic, numbers, text, space, people }, каждое значение 0–2. Уровни: 2 «сильная зона», 1 «рабочий уровень», 0 «зона роста».  

### 7.3. Ценности и условия

`valuesTop3` — ID трёх ценностей с рангами 1–3; `valuesLeast2` — ID двух ценностей «наименее важно»; `needsTop3` — ID трёх условий, выбранных в 4А. Оценки 1–5 по условиям сохраняются, но в формулу не входят (используются только для показа).  

### 7.4. Интерес к сферам

Для каждой сферы: `rawInterest` = сумма оценок двух вопросов SPH с этой сферой (диапазон 2–10).

### 7.6. Формула


| Слагаемое | Формула | Диапазон |
|---|---|---|
| scoreInterest (A) | 2 × rawInterest | 4–20 |
| scoreRiasec (B) | 3 × riasec[t1] + 2 × riasec[t2] + 1 × riasec[t3], где t1–t3 — типы из профиля сферы | 0–30 |
| scoreAbility (C) | 3 × domains[d1] + 2 × domains[d2] + 1 × domains[d3], где d1–d3 — домены из профиля сферы | 0–12 |
| scoreValues (D) |  |  |
| scoreNeeds (E) | +1 за каждое условие профиля, входящее в needsTop3 | 0–3 |
| total | A + B + C + D + E | максимум 71 |
| percent | max(0, round(total ÷ 71 × 100)); округление половины вверх | 0–100 |


### 7.7. Сортировка сфер

Сферы сортируются по `total` по убыванию. При равенстве выше стоит сфера с большим `scoreInterest`, затем с большим `scoreRiasec`, затем в порядке списка: business, finance, it, engineering, biology, telecom, public_service. Если у соседних в рейтинге сфер разница процентов меньше 5 п. п., на экране они помечаются как «равноценные».  
Уровни совпадения: 60 % и выше — «сильное», 45–59 % — «заметное», ниже 45 % — «слабое».

### 7.10. Эталонная реализация (псевдокод)


```js
const TOTAL_MAX = 71;<br>function compute(a, cfg) {<br>  // 1. RIASEC<br>  const riasec = {R:0, I:0, A:0, S:0, E:0, C:0};<br>  for (const q of cfg.pairs)                    // INT01..INT15<br>    riasec[a.pairs[q.id] === 'A' ? q.typeA : q.typeB]++;<br> <br>  // 2. Domains<br>  const domains = {logic:0, numbers:0, text:0, space:0, people:0};<br>  for (const t of cfg.tasks)                    // TSK01..TSK10<br>    if (a.tasks[t.id] === t.correct) domains[t.domain]++;<br> <br>  // 3. Spheres<br>  const rows = cfg.spheres.map((s, order) => {<br>    const raw = a.interest[s.q1] + a.interest[s.q2];<br>    const A = 2 * raw;<br>    const B = 3*riasec[s.riasec[0]] + 2*riasec[s.riasec[1]] + riasec[s.riasec[2]];<br>    const C = 3*domains[s.domains[0]] + 2*domains[s.domains[1]] + domains[s.domains[2]];<br>    let D = 0;<br>    for (const v of s.values) {<br>      if (a.valuesTop3.includes(v))   D += 2;<br>      if (a.valuesLeast2.includes(v)) D -= 2;<br>    }<br>    let E = 0;<br>    for (const n of s.needs) if (a.needsTop3.includes(n)) E += 1;<br>    const total = A + B + C + D + E;<br>    const percent = Math.max(0, Math.round(total / TOTAL_MAX * 100));<br>    return {id: s.id, order, A, B, C, D, E, total, percent};<br>  });<br> <br>  // 4. Sort: total desc, A desc, B desc, config order<br>  rows.sort((x, y) => y.total - x.total \|\| y.A - x.A \|\| y.B - x.B \|\| x.order - y.order);<br> <br>  // 5. Consistency<br>  let mismatches = 0;<br>  for (const k of cfg.checks) {<br>    const typeCheck = a.checks[k.id] === 'A' ? k.typeA : k.typeB;<br>    const linked = cfg.pairs.find(p => p.id === k.linked);<br>    const typeMain = a.pairs[linked.id] === 'A' ? linked.typeA : linked.typeB;<br>    if (typeCheck !== typeMain) mismatches++;<br>  }<br>  return {riasec, domains, spheres: rows, mismatches};<br>}
```

## 13. Пример для приёмки

### 13.3. Критерии приёмки

1. Расчёт на данных из 13.1 даёт ровно значения из 13.2, код интересов ICE и `mismatches` = 0 при проверочных ответах, совпадающих с основными.
